# 小满童装 · 选款与报价中台

> 一句话：把客户嘴里的「幼儿园演出要穿什么 / 90 码还是 110 码」，在 10 秒内变成**款式 + 尺码 + 报价 + 可直接发走的资料包**。

零安装、离线可用。双击 `启动.bat`（或直接打开 `index.html`）即可使用，不需要服务器、不需要联网。

**两个入口**（首次打开先选语言，再登录；登录窗默认只给客户登录，在窗顶 Logo + 标题处**双击**才解锁员工 / 老板入口，退出登录后自动收起）：

| 入口 | 怎么进 | 能看到什么 |
|---|---|---|
| 客户 | 用**任意联系方式**登录（WhatsApp / 手机 / 邮箱 / 微信 / Telegram / Viber），填个称呼即可 | 选款、产品库、参考价、自己的报价单与售后记录；看不到内部线索、成本和别人 |
| 体验版 · 客户 | 点「⚡ 体验版 · 客户」，什么都不用填 | 客户版的全部功能，顶栏标「体验版 · 客户」 |
| 体验版 · 员工 | 点「⚡ 体验版 · 员工」，不用访问码 | 全部页签**只读**：能看客户浏览，发送/导入/改数据被禁用，顶栏有横幅提示 |
| 员工 | 访问码 **`XM2026`**（老板码 `XMBOSS`，都在 `assets/auth.js` 顶部可改） | 全部页签 + **客户浏览**：客户搜了什么、看了哪些款、有没有打开报价单，可直接按他的联系方式发消息 |

> 员工 / 老板入口只在本次打开期间解锁。访问码在 `assets/auth.js` 顶部（`STAFF_CODE` / `BOSS_CODE`）可改，改完同步本文与 `docs/使用说明.md`。

> 客户登录后，报价单会自动填成他本人；员工端点「发送」会拉起 WhatsApp 或邮件客户端，内容可先改再发。资料包是员工端的动作，客户不单独打包。

## 1. 现在就能回答的三个问题

| 客户怎么说 | 系统怎么答 | 在哪 |
|---|---|---|
| 「幼儿园演出要穿什么？」 | 先给候选款 + 3 个消歧问题（身高体重 / 水洗标 / 演出场合），不是瞎推一个款 | 智能选款 |
| 「孩子 105cm、17kg，90 还是 110？」 | 14 个尺码段对照（身高 / 体重 / 胸围）+ 适穿关系，再带出阶梯价与报价单 | 尺码适配图谱 → 报价单 |
| 「把资料发我」 | 封面 + 报价 + 每款一页（款图 / 款号对照 / 尺码段 / 面料克重 / 质检摘要）+ 发货确认页，一次生成，可打印 PDF 或打包 ZIP | 资料包 |

## 2. 30 秒上手

1. 双击 **`启动.bat`** → 浏览器自动打开 `http://127.0.0.1:8765/index.html`
   - 服务在**后台静默运行**，不用保持任何黑窗口；要关闭服务双击 `停止.bat`
   - 没有 Node/Python 也能用：脚本会自动改为直接打开 `index.html`（功能基本一致）
   - 如果浏览器报「127.0.0.1 拒绝连接」= 后台服务没在跑，双击 `启动.bat` 即可（脚本会等端口起来再开页面）
2. 顶部搜索框输入 `奶油小方 圆领卫衣 110 码 300 件`，回车 → 看候选款、依据链和尺码段
3. 点「加入报价」→ 切到「报价单」→「生成报价单」→ 浏览器打印里选「另存为 PDF」

其他能直接搜的说法：`女童 碎花连衣裙 110 120 150 件`、`云朵裙 110`、`DR2601001`、`6972026112300`、`110 加绒卫衣`、客户的原话 `Necesitamos vestidos para niña de 4 años, 300 pzas`。

搜索框认的是系列名 / 尺码段 / 款号 / 编号 / 品类词 / 面料词 / 数量，**不直接解析「105cm 17kg」**——先按 `docs/使用说明.md` §4.2 的尺码段表把身高体重翻成 100 / 110，再搜。

键盘：`Ctrl/Cmd + Enter` 开始匹配，`Esc` 关弹层。

## 5. 数据：规模、来源、边界

| 项 | 数量 | 来源 |
|---|---|---|
| SKU / 款号 | 272 | `build/make-kids-data.mjs` 生成（演示数据） |
| 编号 / 别名 | 613 | 款号 119 / 内部款号 119 / 条码 EAN 119 / 客户款号 119 / 旧款号 84 / 竞品款号 53 |
| 款式系列 / 尺码段 | 26 / 14 | 人工整理（云朵泡泡、奶油小方、小恐龙…；59–66 到 160） |
| 适穿关系 | 44 | 人工整理，**全部带置信度与来源**：高 20 / 中 17 / 低 7 |
| 质检报告 | 12 | 示例结构：GB 31701-2015 / GB 18401-2010 / OEKO-TEX 100 / 起球 / 色牢度 / 缩水率 |
| 面料 | 6 | 精梳纯棉 / 莫代尔 / 摇粒绒 / 涤纶防水布 / 竹节棉 / 羊毛混纺 |
| 品类 | 8 | 连衣裙 46 / 卫衣 40 / T恤 44 / 外套 36 / 裤装 38 / 套装 26 / 家居服 22 / 连体衣 20 |
| 客户 / 线索 | 8 / 8 | 演示数据 |

**必须说清楚的三件事：**

1. **价格、MOQ、交期、客户名、质检报告号都是演示数据**，不是公司真实报价，也不能当验货依据。参考价区间 $3.47–46.05/件，MOQ 50–200 件，都是生成器给的占位值。上线前请用真实商品表替换（产品库 → 导出 CSV → 改 → 数据导入）。交期文案目前还有两套口径：客服浮窗写「现货 3–7 天，改色 / 换面料 / 换标 15–25 天」，报价单页脚写「定金后 25–35 天」，对外前先统一成一条。
2. **适穿关系 44 条里 0 条「已确认」**：高 20、中 17、低 7。系统里每条都标了置信度和来源，并进入「待复核」队列；低置信度的不得直接对大货报价。这是诚实的做法，也是这个库能长期用下去的前提。
3. **图片分清两种**：`assets/img/p/` 的 272 张款式图是**程序绘制的款式示意**（900×1200，按款号参数生成，不是实拍，不能当验货依据）；`assets/img/site/` 的站内实拍图来自 **Burst（Shopify 免费商用图库，免署名）**，可商用，但不要二次转授权、不要再标注成自家拍摄。质检报告是示例结构，报告编号与实验室名称均为演示。

自带一个**纠错闭环**：销售在「尺码适配图谱」新增关系 → 进待复核队列 → 版房确认后变「已确认」→ 下次匹配的置信度自动提高。当前最高只能到「高」（+10 分），「已确认」是 +14 分——这个差距就是复核要补的活。

## 6. 重新生成数据与图片

```bat
cd /d E:\湖北\tongzhuang
node build\make-kids-data.mjs        :: → assets/data.js + data/db.json
node build\make-db.mjs               :: → data/xiaoman.db（SQLite，14 表 + 2 视图）
python build\make_xlsx.py            :: → data/导入模板.xlsx（8 个 sheet）
python build\make_kids_images.py     :: → assets/img/p/ 272 张款式图 + logo（约 4–5 分钟）
node build\make-kids-i18n.mjs        :: → assets/i18n.js（只在改界面文案时需要）
```

**顺序很重要**：`db.json` 是唯一数据源，SQLite、Excel 模板、前端快照都从它派生。改了主数据生成器，就把上面 2–4 行一起重跑，否则三处的口径会不一致。

- Node 侧：`make-db.mjs` 用的是 Node 内置的 `node:sqlite`，需要 **Node 22+**（本机 v24）。跑完会打印 `data/xiaoman.db 已生成` 和各表条数。
- Python 侧：`make_kids_images.py` 需要 Pillow（`python -m pip install pillow`），`make_xlsx.py` 需要 openpyxl（`python -m pip install openpyxl`）。
- 只想先看效果，可以只画前 20 张：`python build\make_kids_images.py 20`（会顺带重画 logo）。全量跑完会打印 `OK 272 images + logo`。
- 款式图读 `build/kids-image-spec.json`（由 `make-kids-data.mjs` 生成，别长期手改——重跑数据生成器会覆盖）。要改颜色 / 图案 / 版型，改数据生成器后重跑；只想试画法，可临时改 spec 再单独跑一次 `make_kids_images.py`。
- **`data/xiaoman.db` 与 `data/导入模板.xlsx` 是派生文件，不要手改**：改完会在下一次重跑时被覆盖。要给 IT / BI 长期用的数据以 `data/db.json` 为准，SQLite 只是方便 `SELECT` 的副本。
- `docs/方案说明.docx` 不会自动更新：改完 `docs/方案说明.md` 后重跑 `python build\md2docx.py`，否则 Word 里还是旧内容。

日常改数据不需要跑脚本：直接在「数据导入」里粘贴 CSV，改的是本机浏览器存储（`localStorage`），可随时「导出全量快照」备份，或「恢复默认数据」回滚。

## 7. 常见问题

**双击后浏览器没打开？** 手动打开 `index.html` 也行；或地址栏输入 `http://127.0.0.1:8765/index.html`。

**改了数据，换台电脑就没了？** 正常。本机数据存在浏览器里；要多人共用，把 `data/store.json` 那套服务端接口放到公司内网（见 `docs/部署到服务器.md`）。

**搜「110」出来一堆款，是不是不准？** 不是。110 是尺码段，不是款号——同一个码段对应几十个款。先按品类（连衣裙 / 卫衣 / 外套）或场景（演出 / 入园 / 家居）收窄，再让客户确认面料和颜色。

**客户说 110 结果穿小了？** 先核水洗标：外单的 4T / 5T 和国标 110 / 120 是两套码表，系统里明确提示「两个码表的实际尺寸差 2cm」。按实测身高体重定码，别按年龄。

**打印出来图片是空白？** 打印对话框里勾选「背景图形」，并把缩放设为「默认」。

**能接孚盟 CRM / 进销存吗？** 能。`data/xiaoman.db` 是标准 SQLite（14 表 + `v_style_profile`、`v_size_band_fit` 两个视图），直接 `SELECT` 或接 BI；要给系统对接的用 `data/db.json`。字段见「数据导入 → 字段字典」或 `docs/方案说明.md` §8.3。

**为什么资料包里的质检报告只有几个款有？** 库里只有 12 份质检报告（对应 12 个款）。其余款发资料时写「可提供同面料同工艺的检测报告」，不要拿别的款的报告顶。
